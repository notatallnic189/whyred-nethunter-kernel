guide-wireguard - WireGuard tunnels on a 4.4 whyred, without touching the ROM

DESCRIPTION

Since v1.2, WireGuard is compiled straight into the kernel image (CONFIG_WIREGUARD=y): it is there at boot, before Android finishes starting, no module to load. Check it once and you never think about it again:

$ adb shell su -c "dmesg | grep -i wireguard"
wireguard: WireGuard 1.0.20210606 loaded. See www.wireguard.com

History, for those on older zips: v1.0.0 to v1.1.1 shipped a signed out-of-tree wireguard.ko built from wireguard-linux-compat instead, because not every ROM tree has the option. Since the built-in one loads first, the extra module was dead weight, and v1.2 dropped it from the zip. Either way, the kernel dataplane is the real one: wg-quick and the Android WireGuard app are just clients on top.

SETUP

Nothing to load on v1.2: the dmesg line above is the whole setup. On a v1.1.x zip the module needs a manual load first (insmod /data/adb/modules/ak3-helper/system/lib/modules/wireguard.ko). Then prove the interface type exists on whatever kernel you run:

$ adb shell su -c "ip link add dev wg0 type wireguard"
$ adb shell su -c "ip link del wg0"

If this fails with Operation not permitted even under su, the running kernel predates v1.1.0. Check uname -a first, flash a current zip second.

CONFIG

Bring a config from wherever tunnels normally come from: your own server, a provider export, the WireGuard app QR. Standard /etc/wireguard/wg0.conf format:

[Interface]
PrivateKey = <your private key>
Address = 10.66.66.5/32
DNS = 10.66.66.1

[Peer]
PublicKey = <server public key>
Endpoint = 203.0.113.10:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25

wg-quick comes from wireguard-tools inside the Kali chroot (installed from the NetHunter app). From the chroot as root:

$ wg-quick up /etc/wireguard/wg0.conf
$ wg show
interface: wg0
  public key: ...
  peer: ...
  endpoint: 203.0.113.10:51820
  transfer: 1.2 KiB received, 4.8 KiB sent

A growing transfer with a recent latest handshake line is the proof of life. Stop with wg-quick down wg0.

TWO WAYS TO RUN IT

  • Chroot side: the path above, full control, scripts and hooks work like any Linux box. Right choice for pentest workflows where the phone routes the team.
  • Android side: the official WireGuard app speaks to the same kernel module, so you can keep a tunnel up during normal daily use without touching the chroot. Import the same config, one tunnel at a time unless you like routing puzzles.

BUGS

  • AllowedIPs = 0.0.0.0/0 routes EVERYTHING through the tunnel, including adb over network. Local adb over USB survives, wireless debugging does not.
  • Deep sleep can pause keepalives on aggressive battery savers. Exclude the chroot or the WireGuard app from battery optimization if the handshake goes quiet.
  • On v1.1.x zips the module is built against that exact kernel tree, vermagic locked: a module from another whyred kernel will not load, by design. On v1.2 the point is moot, it is inside the image.
